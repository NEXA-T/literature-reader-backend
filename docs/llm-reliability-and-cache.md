## Общий лимит 8 секунд

`GigaChatClient.analyze_text` ограничен одним `asyncio.timeout(8.0)` на весь
промах кэша: OAuth, ожидание токен-лока, генерацию, обновление токена и повтор
невалидного JSON. Это не отдельные 8 секунд на каждую попытку. Дополнительно
httpx ограничивает сетевые операции тем же максимальным значением.

`GIGACHAT_TIMEOUT_SECONDS` по умолчанию 8.0. Для обратной совместимости старое
значение 60 не ломает загрузку настроек, но фактический лимит всё равно
`min(8.0, configured_value)`. Меньшее значение допускается. При превышении
срока либо `httpx.TimeoutException` выбрасывается `LLMTimeoutException`,
подкласс `GigaChatUnavailableError`. Ошибочный запрос не кэшируется.
Внешняя отмена запроса не превращается в таймаут.

Таймаут основан на кооперативной отмене asyncio. Он ограничивает ожидание
асинхронного провайдера, а не способен прервать произвольный блокирующий
сторонний код/зависшую ОС. Штатный async httpx и тестовый транспорт отменяются.

## Процессный кэш

Кэш общий для экземпляров клиента в одном процессе. Это важно: существующий
`explain_service` создаёт/закрывает GigaChatClient при каждом HTTP-запросе.
Локальный словарь внутри экземпляра в такой архитектуре не помог бы.

Идентификатор запроса строго соответствует заданной паре:

```python
sha256(json.dumps((selected_text.lower(), context[:100]), ensure_ascii=False).encode())
```

Дополнительная защита:

- пространства кэша разделены по ключу доступа, модели, scope, URL, промпту и TTL;
  сам ключ доступа не сохраняется открытым текстом в идентификаторе;
- перед выдачей сравнивается SHA-256 полного `context` и `book_title`:
  совпадение первых 100 символов не заставит вернуть ответ от другой сцены;
- сохраняются только успешно провалидированные `AIAnalysis`;
- запись и выдача используют копии модели, поэтому изменение объекта
  вызывающим кодом не портит следующий ответ;
- TTL по монотонным часам — 300 секунд по умолчанию, настройка
  `GIGACHAT_CACHE_TTL_SECONDS`; 0 отключает кэш;
- максимум 256 записей на процесс, удаление истёкших записей и LRU-вытеснение;
  доступ защищён коротким RLock без сетевых операций под ним.

При коллизии усечённого контекста безопасно выполняется новый запрос;
одна запись с этим digest заменит предыдущую. При перезапуске кэш исчезает,
между несколькими worker-процессами не разделяется. Одновременные первые
запросы до появления готовой записи могут оба обратиться к модели.

## image_prompt и ограничения галлюцинаций

Промпт требует конкретную видимую сцену, одно английское предложение до
150 символов, без абстрактных понятий, буквального изображения идиом и
неописанных деталей. Pydantic принудительно ограничивает длину 150 символами
и отклоняет нелатинские буквы/строку без английских букв. Нарушение формата
вызывает существующий повтор в пределах общего срока.

Эта проверка букв не является полноценным определением языка: например,
французский текст латиницей она не отличает от английского. Смысловую
конкретность и отсутствие любых галлюцинаций одной схемой гарантировать
нельзя; английский и конкретная сцена заданы промптом и проверены на
сохранённом реальном примере.

JSON null сохраняется допустимым для image_prompt и slang_or_etymology
согласно контракту №11 и критерию теста null. При недостатке контекста
клиент не вынуждает модель придумывать сцену ради непустой строки.
