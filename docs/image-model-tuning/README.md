# Калибровка модели генерации изображений

Задача [#51](https://github.com/NEXA-T/literature-reader-backend/issues/51). Сравнили три модели GigaChat на трёх сценах из [бенчмарка иллюстраций](../demo-assets/scenes.json) и повторили сравнение Max и GigaChat-2 на четвёртой сцене. Использовали один системный промпт, одинаковое описание каждой сцены и один стиль. Порядок моделей меняли между сценами. Кэш обходили, запускали по одному запросу с лимитом 40 секунд, как в `/api/v1/generate-image`.

Публичный API GigaChat вызывает встроенную функцию `text2image` через `function_call: auto`. В этом API нет документированного параметра `steps`, поэтому сравнивали значение `model`. [Документация GigaChat](https://developers.sber.ru/docs/ru/gigachat/guides/images-generation).

| «Гордость и предубеждение» | [22,642 с](06_fine_eyes_GigaChat-2-Max.jpg) | Таймаут | [15,053 с](06_fine_eyes_GigaChat-2.jpg) |

| Медиана успешных вызовов | 22,635 с | — | 18,098 с |
| Среднее успешных вызовов | 22,640 с | — | 18,098 с |

Время измерено от вызова клиента до получения байтов. Оно включает OAuth, запрос к модели, скачивание и ожидание очередного опроса. На четырёх парных сценах GigaChat-2 был быстрее на 1,48–7,60 с. Среднее и медиана сократились примерно на 20%. В диапазон 15–20 секунд попали два из четырёх успешных вызовов. [Первичный лог](timings.json).

На сцене с пустым стулом отдельно измерили время ответа `POST /chat/completions`. Оно сократилось с 21,490 до 13,931 с. Это время HTTP-запроса к сервису, который включает внутреннюю генерацию. Точное время работы диффузионной модели сервис отдельно не сообщает. [Лог этапов запроса](timings-http.json).

В промежуточном прогоне GigaChat вернул HTTP-ошибки для обеих моделей на двух сценах. Код статуса в том прогоне не сохранился. Одну сцену успешно повторили в обеих конфигурациях. Ошибочные вызовы не вошли в замеры времени готового изображения. [Промежуточный лог](timings-http-errors.json).

## Визуальная проверка

Сравнивали соответствие основным деталям сцены, книжный стиль, заметные артефакты и читаемый текст. По одной иллюстрации на сочетание сцены и модели.

| Сцена | Наблюдение |
| --- | --- |
| Алиса и Мышь | У обеих моделей есть ребёнок в голубом платье, мышь и лесной пруд. GigaChat-2 поместил мышь на ладонь вместо земли рядом с ребёнком. |
| «Гордость и предубеждение» | Обе модели передали костюмы и комнату эпохи Регентства. Max изобразил двух похожих персонажей рядом, GigaChat-2 добавил раскрытую книгу с пустыми страницами. Обе версии передали позу менее точно, чем просил промпт. |
| Скрудж и Фред | Обе версии передали контраст хмурого Скруджа и улыбающегося Фреда. В версии GigaChat-2 герои взаимодействуют лицом к лицу. |
| Пустой стул у двери | Обе версии сохранили пустую комнату, закрытую дверь и тёплый свет. Max изобразил стул, GigaChat-2 заменил его деревянной скамьёй. |

На восьми изображениях сохранился иллюстративный стиль. Читаемых надписей и явных дефектов при визуальной проверке не обнаружено. GigaChat-2 сохранил ключевой смысл сцен, хотя в отдельных случаях изменил предмет или позу. Выборка мала, поэтому оценка применима к этим примерам.

## Интеграция

`/api/v1/generate-image` использует `GIGACHAT_IMAGE_MODEL=GigaChat-2` по умолчанию. Чтобы вернуться на Max, укажите `GIGACHAT_IMAGE_MODEL=GigaChat-2-Max` в локальном окружении. `GIGACHAT_MODEL` задаёт модель текстового анализа. Кэш изображений учитывает выбранную модель, промпт и стиль.

Повторить прогон из корня репозитория с настроенным локальным `.env`:

```powershell
python -m scripts.benchmark_image_models --env .env --output .image-tuning-run
```

Скрипт сохраняет изображения и JSON с длительностью полного вызова, HTTP-этапами и причинами заглушек.
