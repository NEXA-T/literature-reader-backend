# Задача #9: подключение к GigaChat API

Изолированный скрипт `test_gigachat.py` использует стандартную библиотеку Python
3.10+; FastAPI, Docker и установка pip-пакетов не нужны.
Получает OAuth-токен и отправляет тестовый запрос. TLS-проверка включена всегда.

## 1. Получить доступ

1. Откройте официальную инструкцию регистрации:
   https://developers.sber.ru/docs/ru/gigachat/quickstart/ind-create-project
2. Перейдите по ссылке «личный кабинет», войдите через Сбер ID.
3. Создайте проект типа **GigaChat API**.
4. В проекте откройте **Настройки API → Получить ключ**.
5. Сохраните Authorization Key либо пару Client ID + Client Secret локально.
   Секрет показывается однократно. Не отправляйте его в чат или на GitHub.
6. Проверьте scope, доступную модель и остаток токенов в кабинете.

На 04.10.2026 документация сообщает: с 01.09.2026 новые клиенты и клиенты,
ранее не покупавшие пакеты, оплачивают модели через Cloud.ru. Доступность
бесплатных запросов нужно проверить в своём кабинете. Если кабинет выдаёт
ключ Cloud.ru вместо GigaChat Authorization Key, этот OAuth-скрипт к нему
не подходит: сначала уточните API и схему авторизации, не подставляйте ключ.
Источник: https://developers.sber.ru/docs/ru/gigachat/individuals-quickstart

## 2. Запуск в PowerShell

Из каталога `literature-reader-backend`:

```powershell
py -3 --version
Copy-Item .env.example .env
notepad .env
py -3 test_gigachat.py
```

Если команда `py` отсутствует, установите Python 3.10+ либо используйте полный
путь к установленному `python.exe`. В `.env` заполните `GIGACHAT_AUTH_KEY`
**без** `Basic `; либо оставьте его пустым и заполните оба поля Client ID и
Client Secret. Можно вообще не сохранять секрет в файл: при пустых полях
скрипт запросит Authorization Key скрытым вводом. Переменные окружения
имеют приоритет над `.env`. Формат файла простой: одна запись `KEY=value`
на строку, без многострочных значений и подстановок.

## 3. Сертификаты

Сначала попробуйте запуск с системными доверенными сертификатами.
При ошибке TLS скачайте PEM-сертификат НУЦ Минцифры по ссылкам официальной
инструкции: https://developers.sber.ru/docs/ru/gigachat/certificates

Сохраните файл, например `certs/russian_trusted_root_ca_pem.crt`, и задайте:

```dotenv
GIGACHAT_CA_BUNDLE=certs/russian_trusted_root_ca_pem.crt
```

Скрипт добавляет этот сертификат к системным доверенным корням только для
своих запросов. Если нужна цепочка, используйте PEM-файл с необходимыми
корневым и промежуточным сертификатами. Проверка сертификатов не отключается.

## 4. Результат и сдача

После реального успешного запроса терминал покажет статус OAuth, модель,
запрос, фактический ответ модели и статус успешного подключения.
Ответ заранее не задан; даже если модель ответит несколькими словами,
успешный ответ подтверждает подключение.

Сделайте скриншот **реального** результата без ключей и содержимого `.env`.
Прикрепите его в комментарий к задаче #9 самостоятельно. До такого запуска
задача не считается проверенной. Офлайн-тесты не заменяют запрос к API.

Ветка подготовлена от `develop`: `codex/gigachat-api-smoke-test`.
В PR обратно в `develop` укажите `Closes #9` и результат реального запуска.
Не публикуйте `.env`, ключи, access token или скриншоты кабинета с секретами.

## Ошибки

- HTTP 401: неверный Authorization Key / Client Secret.
- HTTP 400: проверьте scope в кабинете.
- HTTP 402/403: проверьте тариф, остаток токенов, права и доступность модели.
- HTTP 429: повторите позже.
- TLS: проверьте сертификат и `GIGACHAT_CA_BUNDLE`.
- Сетевая ошибка: проверьте соединение, VPN/прокси и доступ к порту 9443.

Официальный протокол OAuth и пример запросов:
https://developers.sber.ru/docs/ru/gigachat/quickstart/ind-using-api

## Проверка 04.10.2026

Реальный запуск прошёл успешно: OAuth получен, модель GigaChat ответила «Да».
Адрес api.giga.chat из текущей сети завершался сетевой ошибкой.
Использован альтернативный официальный адрес через локальную настройку:
GIGACHAT_CHAT_URL=https://gigachat.devices.sberbank.ru/api/v1/chat/completions
Сертификат Минцифры добавлен через GIGACHAT_CA_BUNDLE, TLS-проверка включена.
Секреты и токен в вывод не включены. Скриншот терминала ещё нужно приложить к #9.
