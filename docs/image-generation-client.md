# ImageGenerationClient — задача №40

Провайдер: встроенный `text2image` **GigaChat**, работающий с уже полученным
ключом. Это API генерации изображений, а не функция распознавания Vision.
FusionBrain отдельно не подключён: он потребовал бы отдельные ключи, а
задача допускает GigaChat как альтернативу.

## Интерфейс

`app/services/image_generation_client.py`:

```python
from app.services.gigachat_settings import GigaChatSettings
from app.services.image_provider import GigaChatImageProvider
from app.services.image_generation_client import ImageGenerationClient

settings = GigaChatSettings.from_env_file(".env")
settings.model = "GigaChat-2-Max"
async with ImageGenerationClient(GigaChatImageProvider(settings)) as client:
    art = await client.generate("An elderly uncle greets his cheerful nephew in a Victorian office.")
    # art.content: bytes; art.media_type: image/jpeg, image/png или image/svg+xml
    # art.is_fallback / art.reason: явное отличие заглушки от генерации
```

Клиент не меняет HTTP-эндпоинт анализа и не подключает генерацию изображений
к мобильной шторке автоматически. Это готовый сервис для последующей
интеграции. Успех и fallback нельзя смешивать при подсчёте готовых примеров.

## Задача, polling и таймаут

GigaChat `/chat/completions` возвращает UUID картинки после синхронного
вызова text2image. Публичного endpoint постановки задачи/проверки статуса,
аналогичного FusionBrain, здесь нет. Мы не изобретаем такой URL.

Адаптер `GigaChatImageProvider` оборачивает реальный REST-вызов в локальную
async-задачу и предоставляет `submit`, `check`, `cancel`, `aclose`.
`ImageGenerationClient` проверяет её завершение раз в 1.5 секунды (допустимая
настройка 1.5–2). `check` читает локальный статус, а не создаёт повторную
генерацию и не тратит токены. После получения `<img src="UUID">` адаптер
скачивает байты через GET `/files/{UUID}/content`.

Один `asyncio.timeout(15)` ограничивает всю попытку: запуск, OAuth,
генерацию, polling и скачивание. Меньший лимит допустим для тестов;
больше 15 задать нельзя. При таймауте локальная задача отменяется и
убирается из реестра. Удалённый провайдер может продолжать уже начатую
генерацию после разрыва соединения — API не предоставляет здесь операцию
удалённой отмены, поэтому возврат токенов не обещается.

Это отдельный лимит генератора, не лимит 8 секунд анализа задачи №35.
Новых зависимостей нет. TLS-проверка всегда включена, сертификат добавляется
из GIGACHAT_CA_BUNDLE. HTTP-перенаправления не выполняются; произвольные URL
из ответа модели не скачиваются, принимается только UUID из тега img.
Проверяются формат JPEG/PNG по сигнатуре и размер до 10 МБ; это не полноценная
декодерная проверка всех возможных повреждений файла. Реальные пять примеров
проверяются визуально отдельно.

## Стилизация и безопасная калибровка

`prepare_image_prompt` нормализует пробелы и добавляет:

```text
, book illustration style, painterly watercolor and ink, cinematic lighting, no text, no letters, no numbers, no writing, no watermark
```

Отдельный системный промпт `app/services/prompts/image_generation.txt`
задаёт книжную композицию, не натуралистическую сцену и отсутствие букв,
логотипов, надписей и читаемых страниц. Он не меняет системный промпт LLM
из параллельного PR №35 и не ослабляет его лимит 150 символов: суффикс
добавляется уже на стороне генератора.

Два явных литературных оборота можно безопасно развести с буквальным
смыслом: `as dead as a door-nail` → тихая контора с пустым стулом;
`murdering the time` → напряжённое музыкальное выступление. Это адаптация
общеупотребительных литературных смыслов, а не скрытая замена опасного
запроса с целью обойти фильтр. Дополнительная фильтрация отклоняет очевидно
неприемлемые описания и требует ручной проверки. Прочие слова бездумно не
вырезаются, чтобы не портить смысл. Полноценной классификацией безопасности
такой короткий список не является; фильтры провайдера остаются включены.

Если провайдер отказал (blacklist/HTTP 400/403/нет картинки), возвращается
помеченная заглушка, а не делается серия перефразирований для обхода отказа.
Примеры из бенчмарка калибруются вручную с сохранением исходного описания:
это не выдаётся за неотредактированный ответ модели.

## Заглушка и ошибки

`app/assets/fallback-cover.svg` — готовая обложка без букв: градиент, арка,
луна и раскрытая книга. Она возвращается как SVG-байты с `is_fallback=True`
и причиной timeout/network_error/provider_rejected и т. п. Для отображения
нужен клиент, умеющий рендерить SVG. Если мобильному контракту нужны только
растровые файлы, заглушку можно отдельно растрировать при интеграции.

Формат ошибки провайдера, исходные ключи, токены и заголовки авторизации не
попадают в исключения или демонстрационный лог. Некорректный ответ не
сохраняется под расширением .jpg. При отмене внешнего запроса asyncio.CancelledError
сохраняется, при выходе из async with соединения и задачи закрываются.

может быть больше 15 секунд. При отказе модерации повторов с изменёнными
словами нет. Seed и шаги диффузии этим интерфейсом не задаются.

## Тестирование

```powershell
python -m pytest -q
```

Моки проверяют submit → processing → done, интервал, таймаут и заглушку,
сетевой сбой, отказ, повреждённый ответ, URL/UUID, реальные формы запросов
OAuth/chat/file, закрытие соединений и отмену зависшей задачи. Реальные
генерации не запускаются pytest и расходуют токены только по явной команде.

Официальная документация использованного API:
https://developers.sber.ru/docs/ru/gigachat/guides/images-generation

## Фактическая задержка провайдера и офлайн-галерея

Во время живой проверки 27.10.2026 генерация не укладывалась в 15 секунд.
Рабочий клиент вернул заглушки; все попытки сохранены в
`docs/demo-assets/interactive-timeout-log.json`. OAuth отдельно занимал
около 0.8 секунды. Длится сама генерация, а не авторизация.

Для подготовки отчётных артов есть отдельный режим:

```powershell
python scripts/generate_demo_assets.py --env-file "C:\lov3waste\NEXA-T\literature-reader-backend\.env" --offline-assets --attempts 1
```

Он напрямую использует адаптер провайдера, ожидая до 90 секунд, и **не является
проверкой интерактивного клиента за 15 секунд**. В рабочем клиенте лимит не
изменялся. Первый офлайн-прогон дал пять настоящих изображений за 18–30 с
каждое; его артефакты сохранены в `calibration-before`. После визуального
анализа уточнены персонажи, стиль и реквизит; финальные времена есть в логе.

Следовательно, корректно подтвердить: сервис возвращает картинку при её
готовности в пределах срока и fallback при задержке; пять отчётных картинок
реальны, но не подтверждают доступность генерации за 15 секунд на этом
провайдере. Для постоянного показа позднего результата понадобится фоновая
генерация/хранилище и отдельный статусный endpoint. Этого задача-сервис
автоматически не добавляет.
